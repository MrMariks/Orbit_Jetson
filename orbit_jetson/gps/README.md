# Пакет GPS

Приём геолокации: **через браузер** (телефон и ПК в одной Wi‑Fi) или **через облако Firebase** (мост в этой папке).

Настройки в **orbit_jetson/gps/config.py**.

---

## Приём GPS из облака Firebase (мост)

Телефон пишет координаты в Firebase → скрипт **bridge.py** на Jetson/ПК забирает их и шлёт GET на локальный сервер (порт 8765). Одна Wi‑Fi для телефона и ПК не нужна.

### Шаги на Jetson/ПК

1. **Установить зависимость** (из папки `gps` или из корня проекта):
   ```bash
   pip install requests
   ```
   или `pip3 install requests`.

2. **Запустить сервер на 8765**  
   Запустите Orbit_Jetson — он поднимает приём GPS на порту 8765 (значение из `config.py`: `GPS_HTTP_PORT`).

3. **Запустить мост** из папки **gps**:
   ```bash
   cd orbit_jetson/gps
   python3 bridge.py
   ```
   или `python bridge.py`.  
   Либо, если есть права на выполнение:
   ```bash
   ./run.sh
   ```

**Переменные окружения (необязательно):**

| Переменная   | По умолчанию | Описание                    |
|-------------|---------------|-----------------------------|
| `CHANNEL_ID`| `myjetson`    | Канал (путь) в Firebase     |
| `LOCAL_PORT`| `8765`        | Порт локального сервера     |
| `FIREBASE_AUTH_SECRET` | —   | Секрет базы (если приходит 401) |

Если при запросе к Firebase приходит **401**, в проекте включена авторизация. В [Firebase Console](https://console.firebase.google.com) → ваш проект → **Настройки** (шестерёнка) → **Сервисные аккаунты** → внизу блок **Секреты базы данных Realtime Database** — скопируйте секрет. Запуск моста с секретом (подставьте свой секрет):
```bash
FIREBASE_AUTH_SECRET=ваш_секрет_из_консоли python3 bridge.py
```
На Windows (PowerShell):
```powershell
$env:FIREBASE_AUTH_SECRET="ваш_секрет"; python bridge.py
```

Примеры:
```bash
CHANNEL_ID=patrol1 python3 bridge.py
LOCAL_PORT=9000 python3 bridge.py
```

Ссылка на Firebase в **bridge.py** закреплена: `https://gpsjetson-default-rtdb.firebaseio.com`. Путь в базе: **channels/канал** (по умолчанию `channels/myjetson`). В приложении на телефоне нужно писать в тот же путь, например `channels/myjetson`, тело: `{"lat": 52.27, "lon": 76.95}`. Полный URL для записи: `https://gpsjetson-default-rtdb.firebaseio.com/channels/myjetson.json`.

### Если с приложения не приходят данные (мост не получает GPS)

1. **Правила Firebase (Rules)**  
   В [Firebase Console](https://console.firebase.google.com) → ваш проект → Realtime Database → вкладка **Rules**.  
   Пример правил с путём **channels/$channelId** (канал по умолчанию — `myjetson`):
   ```json
   {
     "rules": {
       "channels": {
         "$channelId": {
           ".read": true,
           ".write": true
         }
       }
     }
   }
   ```
   Тогда мост читает `channels/myjetson.json`, приложение пишет в тот же путь.

2. **Куда писать с приложения**  
   Полный URL для записи (REST API):  
   `https://gpsjetson-default-rtdb.firebaseio.com/channels/myjetson.json`  
   Метод: **PUT** или **PATCH**. Тело: `{"lat": 52.27563, "lon": 76.95278}` (широта и долгота числами).  
   Канал по умолчанию в мосте — `myjetson` (путь в БД: `channels/myjetson`); если в приложении другой канал, запустите мост с `CHANNEL_ID=ваш_канал`.

3. **Что смотреть в логе**  
   При запуске Orbit_Jetson мост пишет в консоль. Если видите **«Firebase: доступ запрещён»** — ослабьте Rules (см. п. 1). Если **«Firebase: по пути myjetson нет данных»** — приложение ещё не записало данные или пишет в другой путь; проверьте, что приложение шлёт на `.../channels/myjetson.json` и что на телефоне включена геолокация и есть интернет.

### Почему в статусе «GPS нет» — где именно проблема

При старте мост выводит **диагностику** в консоль. По ней можно понять, на каком шаге обрыв:

| Сообщение в консоли | Причина | Что сделать |
|----------------------|---------|-------------|
| **Firebase: доступ запрещён (401)** | Нет доступа к чтению по пути `channels/myjetson` | Положите секрет в `orbit_jetson/gps/.firebase_secret` или задайте `FIREBASE_AUTH_SECRET` (см. выше). |
| **Firebase: по пути channels/myjetson пусто или нет lat/lon** | В Firebase по этому пути нет данных или нет полей `lat`/`lon` | Убедитесь, что приложение на телефоне пишет в `.../channels/myjetson.json` тело `{"lat": число, "lon": число}`. Включите геолокацию и интернет на телефоне. |
| **Jetson HTTPS:8765 — не удалось подключиться** | Мост не достучался до сервера на 8765 | Запущен ли Orbit_Jetson (сервер на 8765 поднимается при старте). В config: `GPS_HTTP_PORT = 8765`, `GPS_HTTP_USE_HTTPS = True` — мост по умолчанию стучится по HTTPS. Если сервер по HTTP, запустите мост с `LOCAL_HTTPS=0`. |
| **Jetson ... — подключение OK** и **Firebase: данные есть** | Цепочка до моста в порядке | Если всё равно «GPS нет», мост должен дальше слать координаты; через несколько секунд должна появиться строка «GPS отправлен в Jetson» и статус сменится на «GPS ✓». |

## Приём GPS через браузер (одна Wi‑Fi)

### Как пользоваться

### 1. Настройка

В **orbit_jetson/gps/config.py**:

```python
GPS_HTTP_PORT = 8765   # 0 = отключить GPS
DEFAULT_LAT = 52.2756313
DEFAULT_LON = 76.9527796
```

Телефон и ПК — в **одной Wi‑Fi сети**.

### 2. IP ноутбука (ПК)

- **Ноутбук раздаёт Wi‑Fi** (телефон подключён к ноутбуку): у ноутбука обычно **192.168.137.1** (Windows). Адрес не меняется, пока точка доступа включена.
- **Интернет раздаёт другой телефон** (телефон А — точка доступа, к нему подключены ноутбук и телефон с браузером): IP ноутбуку выдаёт телефон А. После подключения ноутбука к точке доступа выполните на ноутбуке **ipconfig** и посмотрите **IPv4** у адаптера Wi‑Fi (например 192.168.43.85). На телефоне откройте в браузере **http://ЭТОТ_IP:8765/**. Пока ноутбук в сети, IP не меняется; если подключались заново — проверьте ipconfig ещё раз.
- Обычная домашняя Wi‑Fi: `ipconfig` → IPv4 в вашей сети.

### 3. На телефоне

1. Запустите Orbit_Jetson на ПК.
2. В браузере на телефоне откройте: **http://IP_ПК:8765/**  
   Пример: `http://192.168.1.100:8765/`
3. Разрешите доступ к геолокации.
4. На странице будет «Координаты отправляются на ПК» и координаты. Страницу можно не закрывать — данные обновляются сами.

В приложении в статусе будет **GPS да**, когда с браузера пришли координаты (и не старше 2 минут).

### 4. Если не работает

- В config задан **GPS_HTTP_PORT = 8765** (не 0).
- Телефон и ПК в одной Wi‑Fi, в браузере указан верный IP ПК и порт.
- Фаервол на ПК не блокирует входящие на порт 8765.
- В логе при старте: `GPS: приём координат на порту 8765 (HTTP). Откройте на телефоне: http://IP_ПК:8765/`

## В коде

```python
from orbit_jetson.gps import get_gps, GpsPosition

gps = get_gps()
pos = gps.get_position()  # GpsPosition(latitude=..., longitude=...)
gps.is_connected()        # True, если с браузера пришли данные не старше 2 мин
```

## Отключение GPS

1. Удалите папку **orbit_jetson/gps/**.
2. В **orbit_jetson/main.py** уберите импорт `get_gps` и передавайте заглушку с `get_position()` и `is_connected()`.
3. В **orbit_jetson/api_client.py** уберите импорт `GpsPosition` из gps.
4. В **orbit_jetson/ui.py** карта и статус «GPS» будут от заглушки.
