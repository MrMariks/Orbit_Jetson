# Промпт: мобильное приложение «GPS‑передатчик» для Orbit_Jetson

Скопируй текст ниже в чат (нейросеть или разработчику), чтобы описать задачу на приложение для телефона.

---

## Режим «через бэкенд» (рекомендуется — не нужна одна Wi‑Fi)

Телефон может слать координаты **напрямую на сервер Orbit_Backend**. Тогда телефон и ноутбук с Orbit_Jetson **не обязаны быть в одной сети** — достаточно интернета у обоих.

**Что делать в приложении:**
- Поля ввода: **URL сервера** (например `https://your-backend.com` без слэша в конце) и **API-ключ** (тот же, что у патруля в админке Orbit_Backend; он же в `api_key.txt` на ПК с Jetson).
- Раз в 2–5 секунд отправлять запрос:
  ```http
  POST {URL}/api/v1/patrol/position
  Authorization: Bearer {API_KEY}
  Content-Type: application/json

  {"latitude": 52.27563, "longitude": 76.95278}
  ```
- Успех: ответ **200 OK**. Ошибка авторизации: **401**. При ошибке сети — показывать пользователю, не падать.

Карта и телеметрия на бэкенде будут показывать позицию патруля по этим данным. Orbit_Jetson на ноутбуке может вообще не получать GPS с телефона — позиция уже есть на сервере.

---

## Задача (режим «напрямую на ПК» — одна Wi‑Fi)

Нужно **мобильное приложение** (Android и/или iOS), которое передаёт **GPS-координаты телефона** на компьютер с запущенной программой **Orbit_Jetson** (патрульный модуль). Передача идёт по Wi‑Fi в одну сторону: телефон → ПК. Браузерный вариант не подошёл — нужен нативный клиент.

## Что делает Orbit_Jetson на ПК

- На ПК поднимается **HTTP-сервер** (порт по умолчанию **8765**, настраивается).
- Сервер принимает **GET-запросы** с координатами в URL:
  ```text
  GET http://IP_ПК:8765/?lat=52.27563&lon=76.95278
  ```
- Параметры:
  - **lat** — широта (float, градусы WGS84, от -90 до 90).
  - **lon** — долгота (float, градусы WGS84, от -180 до 180).
- Ответ при успехе: **200 OK**, тело может быть пустым или `OK`. Без авторизации, без JSON в запросе.
- ПК и телефон должны быть в **одной Wi‑Fi сети** (например, ноутбук и телефон подключены к одной точке доступа или к одному роутеру).

## Требования к приложению на телефоне

1. **Получение GPS**
   - Доступ к геолокации устройства (фоновая или по запросу — как удобнее для сценария «телефон в машине»).
   - Точность: желательно высокая (для навигации/патруля).

2. **Отправка координат на ПК**
   - Периодическая отправка (например, каждые **2–5 секунд**) GET-запроса:
     `http://ВВЕДЁННЫЙ_IP:ПОРТ/?lat=ШИРОТА&lon=ДОЛГОТА`
   - IP и порт пользователь вводит в приложении (ПК может менять IP при переподключении к Wi‑Fi).
   - Формат: обычный HTTP (не обязательно HTTPS для нативного приложения).
   - Если ответ не 200 или нет сети — показывать ошибку/статус, не падать.

3. **Интерфейс**
   - Поле ввода **IP-адреса ПК** (например, `192.168.43.156`).
   - Поле ввода **порта** (по умолчанию `8765`).
   - Кнопка **Старт** / **Стоп** (начать/остановить отправку координат).
   - Отображение статуса: «Отправляю», «Ошибка сети», «Нет доступа к GPS».
   - Опционально: последние отправленные координаты (lat, lon), время последней успешной отправки.

4. **Дополнительно**
   - Сохранение последнего введённого IP и порта (чтобы не вводить каждый раз).
   - Работа в фоне (если платформа позволяет), чтобы при свёрнутом приложении координаты продолжали уходить на ПК.
   - Учти, что интернет на ноутбук/телефон может раздаваться с другого телефона — приложение только шлёт данные по локальной сети на введённый IP.

## Техническая совместимость с Orbit_Jetson

- Метод: **GET**.
- URL: `http://IP:PORT/?lat=ЧИСЛО&lon=ЧИСЛО` (числа с точкой, без лишних параметров).
- Заголовки: стандартные, без авторизации.
- Сервер на ПК слушает на `0.0.0.0:PORT`, то есть принимает запросы с любого устройства в сети.

Реализуй приложение с учётом этого протокола, чтобы Orbit_Jetson стабильно получал координаты и отображал позицию патруля на карте и в телеметрии.
